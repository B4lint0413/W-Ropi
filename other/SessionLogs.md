# Session Logs

This file will contain all the things we've done during the sessions to keep track of the progress we made.

## Preparations (Session 0)
- To start off the work, we certainly needed to plan what will we need and order it. The first thing we chose was the control unit as it will define all the other elements we need. We wanted to use Raspberry Pi as it is lightweight, easily managable, and can run not just a limited micro python like LEGO hubs.
- We planned the whole run, like we will run the wheels at a constant speed and steer the car based off the value we get from the controller. The controller will have two aspects: the walls' distances and the pillars (color, distance and relative place). If we are making it the right way, PID factors will provide us many parameters to finetune it.
- For motors, we had LEGO Spike motors, which are extremly precise. So we bought a Build Hat for Raspberry Pi as it provides the Raspberry 4 LEGO Spike ports (two motors and two ultrasonic sensors).
- We already had a camera which is wide enough and can be connected to the Raspberry Pi directly.
- For starting the program in the competition, we will need a button and a LED as well, for signing the status of the car. For this we will need GPIO extenders, just as bigger spacers for the Build Hat.
- For power supply we planned to use power bank or 9V batteries so we ordered different gadgets to test out the proper way of powering the car.
- So for driving we are using 2 LEGO Spike motors, and for sensing the environment, we planned to use two ultrasonic sensors detecting the walls on the left and right and a camera looking for the pillars.

## Basic navigation (Session 2) 2025.05.23
- As we finally got our order we could test out the proper power supply for the car. So the basic concept was that we need to provide around 9V and 2A for the Build Hat. It can forward 1,5A and 5V to the Raspberry Pi board and to its camera which is more than enough and the spared current is enough for the motors. Our first try was the USB-A to DC cable: it didn't work as it's limited to 5V. The next try with the 5 AA batteries worked perfectly but we didn't want to mess around with 5 rechargable AA batteries. We ordered a voltage booster for USB-C as well so we could use a power bank for power supply. It worked properly even under load as well.
- Next step was to place the 10400mAh battery well. We settled it under the Raspberry Pi behind the camera in the middle. Now we could move on to the navigation.
- We realised soon enough that the weight distribution was uneven, as it didn't have any pressure on the steered front axis. So we needed to move the cage with the power bank and the Raspberry Pi closer to the front and so the camera. After some testing we were satisfied with the new design. 
- We could move on to make the basic navigation. So our concept was that we sense the wall distance with the ultrasonic sensors so we just need to make the proper PID controller to keep the car between the walls. We quickly realised, that ultrasonic sensors only work up to 45 degrees, so we need to handle the steep angle distances as they mean 90 degrees turns the car needs to make. Finetuning the PID factors didn't help us out so we needed to find a new perspective.
- The we found out that the car doesn't actually get the distance difference of the walls from the car as while turning the car measures longer distances than its distance from the wall. We need to track the current orientation of the car so we could multiply the distance with its cos value. Also knowing the orientation gave us a new opportunity to strive to keep parallel with the walls. We added this to the controller so now it corrects itself in really short time and keeps center securely.
